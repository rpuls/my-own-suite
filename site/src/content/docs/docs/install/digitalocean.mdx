This is the fastest way to get a running suite: a small DigitalOcean droplet that installs My Own Suite by itself while it boots. You paste **one command** when you create it, and you never open a terminal on the server.

**What you need**

- A [DigitalOcean](https://www.digitalocean.com/) account (the reference droplet size costs about $24/month — you can destroy it at any time).
- Nothing installed on your own computer. The installer runs entirely on the droplet.

<Steps>

1. **Create the droplet.**

   In the DigitalOcean dashboard, choose **Create → Droplets** and pick:

   - **Image:** Ubuntu **24.04 (LTS) x64**
   - **Size:** at least **2 vCPU / 4 GB RAM** (the Basic shared-CPU tier is fine)

2. **Add the install command.**

   Under **Advanced Options**, enable **Add Initialization scripts (free)** and paste this in the box:

   ```sh
   #!/bin/bash
   curl -fsSL https://get.myownsuite.org | bash
   ```

   That's the whole installer. On first boot the droplet fetches the current reviewed MOS release, works out its own public address, and installs Docker, the MOS platform, and its services. It contains **no passwords and no secrets** — your owner account is created later, in your browser. If you'd rather read it first, open <a href="https://get.myownsuite.org/install.sh">https://get.myownsuite.org/install.sh</a> in a browser.

   Then create the droplet.

3. **Wait for the install to finish.**

   The droplet installs everything itself — typically **5–15 minutes**, occasionally up to 30 on a slow machine. Note the droplet's public IP address from the DigitalOcean dashboard, then visit:

   ```
   https://home.<your-droplet-ip>.sslip.io/
   ```

   For example, if your droplet's IP is `203.0.113.10`, your suite lives at `https://home.203.0.113.10.sslip.io/`. Refresh occasionally; when the setup screen appears, the install is done.

   :::tip[What is sslip.io?]
   `sslip.io` is a public convenience service: any address ending in your IP + `.sslip.io` automatically points at that IP. It means your suite has a working web address instantly, with no domain to buy and no DNS to configure — and MOS obtains a real HTTPS certificate for it automatically (see below).
   :::

4. **Create your owner account.**

   The first visit shows **Create your owner account**. Do this right away — until an owner exists, anyone who knows the address could claim the fresh install. Then continue with [Your first sign-in](/docs/install/first-start/).

</Steps>

## Backup destination

Attach a separate persistent block-storage volume through your provider, format and mount it on this server, then select that mounted volume in Suite Manager. A USB disk attached to your own computer is not visible to a rented server. MOS has no direct object-storage destination today; provider snapshots are an additional provider-managed recovery layer, not a consistency-checked MOS backup. Use encrypted storage and read [Back up and restore](/docs/guides/backup-restore/) before storing data.

## Good to know

- **HTTPS is automatic.** MOS obtains a real (Let's Encrypt) certificate for the generated `sslip.io` address, so your suite is served over HTTPS. The very first load can take a minute while the certificate is issued; if you see a brief certificate warning, wait and refresh. To use your **own** domain with HTTPS on a cloud server, point an A record at the droplet and follow your provider's domain tooling — the built-in [Cloudflare HTTPS setup](/docs/guides/https-domain/) is reserved for self-hosted installs, where MOS controls the machine's network story end to end.
- **Billing:** a powered-off droplet still bills. To stop paying, destroy the droplet (backups first — see [Back up and restore](/docs/guides/backup-restore/)).
- **Other providers:** the same one command works anywhere that gives you a fresh Ubuntu 24.04 server — see [Install on any cloud server](/docs/install/cloud-server/).
- **Prefer to inspect and render locally?** Power users who want to build the install file themselves (for review or air-gapped installs) can use the advanced `install:render` flow described in [Install on any cloud server](/docs/install/cloud-server/#advanced-render-the-install-file-yourself).
