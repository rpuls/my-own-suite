## Verdict

- **Spaghetti fear: unfounded.** The new backend modules form a clean DAG (pure `package-contracts.cjs` leaf, small single-purpose utilities, orchestrators on top, the one potential service cycle broken by constructor injection). No layer violations. External apps reuse the official install/update pipeline instead of growing a second one.
- **Overengineering fear: partially founded**, in specific removable pockets (dead trust tiers, unreachable agent-contract tier, unused schemas, dead frontend code) — listed below. The security/hashing/transaction complexity is otherwise earned by named failure modes.
- **Not ready for the human test pass yet.** Four showstopper bugs (§2), a boot-crash path, and — the key product finding — zero apps are actually rated, so the posture system does not yet make the landing-page claims honest (§4).

## 1. What holds up (do not regress)

- The defining rule ("installed behavior comes from the snapshot, never the repo") is enforced on **both** sides of the privilege boundary: Suite Manager re-verifies snapshot identity+digest on every read; the root agent independently re-derives paths and re-hashes bytes at snapshot, stage, build, activate, and promote. Tests prove installed apps are stable when the repo checkout moves or disappears.
- The plan doc's (unchecked) security review checklist was executed against real code and **passes almost everywhere**: hardened link-refusing tar reader; bounded downloads (time/redirect/bytes/files/gzip `maxOutputLength`); immutable revision resolved before content is trusted; trust never promotable from package-controlled fields; verify-before-parse on every catalog/advisory/cache path; cache stores signed bytes + signature and re-verifies on read; private-key-in-public-slot refused; LF-canonical signing with a CRLF regression test; digest-bound confirmation tokens; strict downgrade/replay blocking; security events structurally URL-free.
- Agent-side reclamation threat-modeling is exemplary: image names derived only from digest-verified on-disk manifests, pattern-fenced tag namespace, no `--force`, failures ignored, post-commit only; tested tampered-sidecar and in-use-image cases; deliberate leak-instead-of-strand compatibility choices tested on both sides.
- External-package identity: namespaced ids enforced *by the agent* (bare-id refusal, suffix==manifest.id), so even a compromised Suite Manager cannot seat an external package in an official runtime identity.
- Migrations are individually transactional and record-after-apply; migration 12's `security_events` rebuild carries rows correctly; legacy instances migrate truthfully or enter `needs-package-recovery`.
- Frontend: shared `Dialog` extended rather than forked; `Notice`/`TextInput`/"Advanced details" used as prescribed; trust and posture always backend-derived; "External · Unverified" survives install and update.
