# Public installer endpoint

The stable entrypoint for `get.myownsuite.org` serves the **published release**: it reads `tag_name` from GitHub's `releases/latest` — the same call the update agent makes, and one GitHub excludes drafts and prereleases from — then pins that tag to its commit SHA. So a new machine starts on the exact commit its own updater considers current, and both installer doors land on the same release. It previously served the tip of `main`, which is the same commit only until the next merge: between releases a fresh install ran unreleased code while its `VERSION` file, and therefore its update check, still reported the last release.

The development entrypoint for `get-dev.myownsuite.org` reads `INSTALL_BRANCH` from its repo-owned Wrangler configuration (`staging`, the default integration target). Point it at whichever branch is under test and redeploy the dev Worker (`npx wrangler deploy` from `infrastructure/installer-endpoint/dev`) before running the DigitalOcean smoke.

Prefer `staging` and leave it there. A Worker left pointing at a short-lived feature branch keeps working until that branch is deleted, and then serves a 503 that a cloud install swallows silently — the machine simply never installs anything. `npm run smoke:do:reset` now refuses to create a Droplet when the endpoint is not serving a launcher, so this fails in seconds instead of after a 30-minute readiness timeout on a paid machine. `/install.sh` exposes either launcher for inspection. Hosted one-line installs select the `public-vps` front door, which enables automatic HTTPS and protected first-owner setup; generic `ssh-bootstrap` remains available for non-public/LAN use.

The Worker asks GitHub for the configured branch tip, validates the returned full commit SHA, and emits a launcher pinned to that SHA. The machine therefore installs one immutable snapshot even if the branch moves during installation. No GitHub or Cloudflare API token is required by the Worker for this public repository.

That last point has a cost worth knowing about: GitHub allows 60 unauthenticated API requests an hour per IP, and Workers egress from shared Cloudflare addresses, so asking on every request produced intermittent `403`s that reached machines as a `503` — and `curl … | bash` turns a `503` into an install of nothing, silently. The Worker therefore remembers the last resolved SHA per branch: fresh answers are reused for a minute without touching GitHub, and if GitHub stops answering entirely the remembered SHA is served for up to a day rather than failing. `X-MOS-Install-Ref-Age` reports how many seconds old the served SHA is; anything above 60 means GitHub is refusing and this is a fallback.

Inspect the endpoint with `curl https://get-dev.myownsuite.org/install.sh`, not `curl -I`. The Worker answers `GET` only, so a `HEAD` request returns 404 and looks like an outage that is not there. Use `curl -sD - -o /dev/null` when you want the headers.
